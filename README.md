# 원신 지도 합치기

원신의 큰 지도(지도 화면)를 앱이 대신 끌어 가며 찍고, 찍은 사진을 한 장으로 합친 뒤 가장자리를 다듬어 주는 Windows 앱이다. C#(.NET 10 + WebView2)으로 만들었다.

이 문서는 처음 받은 사람과 AI 코딩 에이전트가 같이 읽도록 썼다. 오류를 고치거나 더 발전시키려면 **5장(한계)·6장(추측과 못 해 본 실험)·7장(고치는 법)** 부터 보면 된다.

> **지금 상태(2026-11-16, v0.1.0)**: 파이썬 판을 C#으로 옮긴 첫 공개 판이다. 같은 입력에 파이썬 판과 같은 결과가 나오는지 견주며 옮겼고, 실제 원신에서 C# 판으로 두 판(기본 지도·이벤트 그림체 지도)을 찍어 둘 다 완료됐다(5장). 개발 PC 한 대(2560×1440, 한국어 클라이언트)에서만 해 봤다.

## 1. 하는 일과 안 하는 일

| | |
|---|---|
| 하는 일 | 원신 지도 화면에서 마우스 입력(Windows `SendInput`)으로 지도를 끌고, 화면을 찍고(GDI 화면 복사), 이 PC 안에서 합친다 |
| 안 하는 일 | 게임 파일·메모리·통신(패킷)은 읽지도 쓰지도 않는다 |
| 관리자 권한 | 원신이 관리자 권한으로 돌아서, 지도를 끌려면 앱도 관리자 권한이어야 한다. 앱을 켤 때 윈도우가 한 번 묻는다 |
| 통신 | 앱 화면(WebView2)과 앱은 같은 프로그램 안에서 가짜 주소 `https://genshin.test/`로 주고받는다(바깥으로 나가는 요청이 아니다). 앱 코드에는 인터넷에 접속하는 부분이 없다. WebView2 런타임(마이크로소프트 엣지 부품) 자체가 하는 통신은 감사하지 않았다(6장) |

## 2. 처음 쓰는 법

### 2-1. 설치

1. Windows 10 또는 11(64비트). **WebView2 런타임**이 있어야 한다. 윈도우 11에는 기본으로 있고, 윈도우 10도 엣지가 깔려 있으면 대개 있다. 없으면 마이크로소프트의 'WebView2 Runtime(Evergreen)'을 설치한다.
2. 이 저장소의 **[Releases](https://github.com/codle-codle/genshin-map-stitcher/releases)** 에서 `GenshinMap-v…-win-x64.zip`을 받는다. 설치 프로그램이 아니라 압축 파일이다.
3. 압축을 아무 폴더에 풀고 `GenshinMap.exe`를 누른다. 아래 두 경고 창(2-1-1)을 지나면 앱 창(1100×760)이 뜬다. .NET이나 다른 꾸러미를 따로 설치할 필요가 없다(폴더에 다 들어 있다).
4. 이미 켜져 있을 때 다시 누르면 새로 켜지지 않고 그 창이 앞으로 온다.
5. 창을 닫았을 때 붙이기·다듬기·찍기가 아직 돌고 있으면, 창만 숨고 그 일이 끝난 뒤 앱이 꺼진다.
6. 지우기: 압축을 푼 폴더를 통째로 지운다. 앱이 폴더 밖에 남기는 것은 화면 부품(WebView2)의 임시 저장 폴더 `%LOCALAPPDATA%\GenshinMap` 하나다. 이것도 지워도 된다. 레지스트리·시작 프로그램·서비스는 만들지 않는다.

#### 2-1-1. 처음 켤 때 뜨는 경고 두 개

이 앱은 **코드 서명이 없다**(개인 취미 프로젝트라 인증서를 사지 않았다). 그래서 윈도우가 처음 보는 프로그램이라고 두 번 경고한다.

| 순서 | 뜨는 창 | 할 일 |
|---|---|---|
| ① | 파란 창 「Windows의 PC 보호」 (SmartScreen) | **「추가 정보」 → 「실행」**. 받은 사람이 적은 새 파일이면 서명이 있어도 뜨는 창이다 |
| ② | 「이 앱이 디바이스를 변경하도록 허용하시겠어요?」 (관리자 권한, 게시자: 알 수 없음) | **「예」**. 왜 필요한지는 아래 |

- 윈도우 11의 **스마트 앱 컨트롤**이 켜진 PC는 서명 없는 프로그램을 「실행」 단추 없이 막을 수 있다. 이때는 이 앱을 쓸 수 없다. 이 앱 하나 때문에 스마트 앱 컨트롤을 끄는 것은 권하지 않는다.
- 회사·학교 PC처럼 관리자가 정한 정책이 있으면 ①에서 아예 못 넘길 수 있다.

**관리자 권한이 왜 필요한가.** 원신은 관리자 권한으로 켜진다. 윈도우에는 '권한이 낮은 프로그램은 권한이 높은 프로그램 창에 마우스·키보드 입력을 보낼 수 없다'는 규칙(UIPI)이 있다. 마이크로소프트 문서에도 `SendInput`은 같거나 낮은 권한의 프로그램에만 입력을 넣을 수 있다고 나와 있다. 그래서 일반 권한으로 켜면 원신 지도를 끌 수 없다. 이 규칙을 피하는 다른 방법(`uiAccess`)은 코드 서명과 Program Files 설치가 있어야 해서 이 앱에는 못 쓴다. 관리자 권한으로 하는 일은 1장 표와 같다(지도 끌기·화면 찍기·이 PC 안에서 합치기).

#### 2-1-2. 받은 파일이 진짜인지 확인

Releases의 ZIP은 개발 PC가 아니라 **GitHub의 빌드 서버(Actions)가 이 저장소의 소스로 만든 것**이다(`.github/workflows/release.yml`). 두 가지로 확인할 수 있다.

1. **SHA-256**: ZIP 옆의 `.sha256` 파일 값과, PowerShell에서 아래 명령으로 나온 값이 같은지 본다.
   ```
   Get-FileHash .\GenshinMap-v0.1.0-win-x64.zip -Algorithm SHA256
   ```
2. **빌드 출처 증명**: GitHub CLI가 있으면 이 ZIP이 이 저장소의 빌드에서 나왔는지 확인된다.
   ```
   gh attestation verify .\GenshinMap-v0.1.0-win-x64.zip --repo codle-codle/genshin-map-stitcher
   ```

폴더 안 파일 중 서명이 없는 것은 이 앱 파일 4개(`GenshinMap.exe`, `GenshinMap.dll`, `GenshinMap.Core.dll`, `GenshinMap.Win.dll`)와 OpenCV 부품 2개(`OpenCvSharp.dll`, `OpenCvSharpExtern.dll`, nuget.org의 OpenCvSharp5 꾸러미 그대로)다. 나머지 .NET·WebView2 파일은 마이크로소프트 서명이 있다(파일 > 속성 > 디지털 서명). 이 앱은 AI 코딩 도구로 만들었다. 공개 전에 한 점검은 6장 「배포 전 점검」에 적었다. 소스를 직접 보거나 AI 에이전트에게 읽혀 확인해도 된다.

소스에서 직접 만들려면 .NET SDK 10(`global.json`의 판)을 설치하고 이 폴더에서:

```
dotnet publish src/App/App.csproj -c Release -o 게시
```

꾸러미는 nuget.org에서 받는다(`NuGet.Config`). 게시 폴더에 외부 부품 고지(`THIRD-PARTY-NOTICES.txt`, `licenses/`)가 자동으로 모인다.

### 2-2. 찍기

1. 앱 창의 「지도 찍기 시작」을 누른다.
2. 원신으로 가서 지도를 열고(M), 휠로 **끝까지 축소**하고, **땅이 화면 가운데** 보이게 둔다. 전체 화면·창 모드 모두 된다(파이썬 판에서 확인). 확대한 채로 찍는 건 지원하지 않는다(5장 한계 11). **임무 추적은 꺼 둔다.** 켜 두면 화면 가장자리에 붙는 노란 추적 표시가 결과 지도에 같이 찍힐 수 있다(5장 한계 13).
3. **시작 키**(기본 `Home`)를 누른다. 키보드에 Home이 없으면 앱의 「설정」에서 다른 키(예: F8)로 바꾼다.
4. 3초 예고 뒤 찍기가 시작된다. 찍는 동안 마우스는 잠긴다. **클릭하거나 `Esc`나 멈추기 키(기본 `End`)를 누르면 바로 멈추고 마우스가 풀린다.** 앱 창의 멈추기 단추로도 멈춘다.
5. 다 찍으면 소리(밝은 세 음)와 원신 위 알림 띠로 알리고 앱 창이 앞으로 온다. 합치기와 다듬기는 자동이고, 사진이 붙어 가는 모습을 앱 창에서 실시간으로 볼 수 있다. 합치는 동안과 끝난 뒤에 「찍은 사진」 탭에서 찍은 사진을 찍은 순서대로 보고, 눌러서 크게 볼 수 있다(기본은 「지도」 탭).
6. 「원본 그림 열기」로 큰 그림을 열어 확대해 선명도를 보고, 「폴더 열기」로 파일을 가져간다.

시작이 안 되는 자리(예: 지도 바깥의 별만 보이는 곳)에서 시작 키를 누르면, 원신 위에 이유와 할 일이 뜨고 앱은 시작 키를 다시 기다린다. 화면이 통째로 검게 찍히면 원신의 화면 모드(전체 화면·창 모드·테두리 없는 창)를 바꾼 뒤 시작 키를 다시 누른다.

이미 손으로 찍은 사진이 있으면 「이미 찍은 사진으로 합치기」로 넣을 수 있다. 사진은 모두 같은 크기여야 하고, 파일 이름 순서대로 가까운 것끼리 먼저 맞춘다.

### 2-3. 지난 지도와 용량

- 작업 하나(찍은 사진 원본 + 결과 그림)는 450~650MB쯤이다(파이썬 판 실제 판 110~155장 기준).
- 작업은 실행 파일 옆 `작업/` 폴더에 쌓인다. 「지난 지도」에서 ✕로 버린 작업은 **윈도우 휴지통**으로 간다. 휴지통에 안 들어가 바로 영구 삭제가 될 상황(휴지통 크기보다 큰 경우 등)이면 윈도우가 먼저 묻는다.

## 4. 작동 원리

### 4-1. 전체 흐름

```
시작 키(원신 창) → 시작 판정 → 3초 예고(마우스 잠금) → 끌기 모형 보정 → 칸 격자 탐색하며 찍기(사진은 따로 도는 일꾼이 작업 폴더에 넣음)
 → 끝(마우스 풂, 알림, 앱 창 앞으로) → 격자 붙이기(실시간 모자이크) → 테두리 다듬기 → 완성
```

찍기는 앱 안의 작업 스레드에서 돈다. 붙이기·다듬기는 같은 실행 파일을 인자와 함께 **자식 프로세스**로 띄운다(멈추기 = 그 프로세스를 끝냄, 큰 그림 메모리가 끝나면 통째로 돌아옴, 붙이기가 죽어도 앱은 안 죽음). 앱은 자식의 출력 줄(`[match]`·`[live]`·`[seam]`·`[done]` 등)을 읽어 진행률과 실시간 모자이크를 그린다(`Parsers`).

### 4-2. 찍기(`FastCapture`)

- **시작 판정**: 첫 화면의 '지도 점' 비율이 `VOID_MAX`(2%)보다 적으면 지도 바깥으로 본다. 화면이 통째로 검게 찍히면 찍기 불가로 본다. 둘 다, 그리고 보정 실패도 **사진이 0장이면 끝내지 않고** 알림 띠로 이유를 알린 뒤 시작 키를 다시 기다린다(`CaptureRunner`).
- **지도 점**: 밝기 V>80 또는 (V≥58이고 채도 S≥150). 먼바다(V≈70, S≈190)를 지도로 세려고 둘째 조건이 있다.
- **끌기 모형**: `지도 이동 = g(확대 정도) × (마우스 이동 − d0)`, d0 ≈ 18.79px(실측). g는 찍기 시작 때 몇 번 끌어서 잰다(`Calibrate`). 확대 최대 g≈0.66 ~ 최소 g≈1.24(이벤트 그림체 지도에서 잰 값). 기본 지도는 끝까지 축소해도 g≈1.01이다(파이썬 판 실제 판).
- **칸 격자**: 한 칸 = 화면 너비 45%(`STEP_X`), 높이 35%(`STEP_Y`). 지그재그로 가다가 막히면 가장 가까운 '아직 안 간 칸'으로 되돌아간다(BA* 방식). 각 칸 가장자리 띠(`EDGE_STRIP` 12%)에 지도 점이 있으면 그쪽 이웃을 갈 곳으로 적는다.
- **끌기**(`GenshinScreen.Drag`): 지도 아이콘 위를 누르면 안 끌리므로 가장 민무늬인 곳을 누른다(`Geometry.PressSpot`). 처음 24px를 0.06초에 천천히(빠른 끌기는 처음 1~2걸음을 게임이 버림) → 0.05초 쉼 → 나머지를 끝으로 갈수록 느리게 0.30초 → 0.40초 멈췄다 놓는다(멈추면 관성이 없다). 걸음은 8ms이고 `PreciseClock`(고해상도 대기 타이머)으로 잔다. 보통 타이머(15.6ms 단위)로 자면 끌기가 두 배쯤 느려져 끌기 모형이 안 맞는다.
- **빠른 확인**(`FastCompare`): 놓은 뒤 화면을 끌기 전 화면과 견준다. 끈 축으로 가설 8개(예상대로 감, 60~360px 덜 감, 60px 더 감)를 놓고 예상이 뚜렷이 맞으면 '맞음', 다른 가설이 맞으면 '다름', 어느 것도 아니면 '모름'. '맞음'이어도 점수가 `FAST_MIN_SCORE`(0.05)보다 낮으면(바다뿐인 화면의 잡음) '모름'으로 친다.
- **'모름'이면 끈 축 재 보기**: 끈 만큼 갔다고 바로 적지 않고, 끄는 축만 넓게 밀어 보며(`AxisScan`) 몇 px 갔는지 잰다. 다 갔으면 그 값을 쓰고, 덜 갔거나 더 갔으면 천천히 잰다.
- **멈춤 기다림·천천히 재기**: '다름'이거나 아직 움직이면, 멈출 때까지(최대 `SETTLE_MAX` 12초) 기다리며 끌기 전 화면과 맞추기(`ViewShift`), 이미 찍은 사진들과 맞추는 절대 위치(`AbsolutePosition`)로 잰다. 그래도 못 재면 추정 표시를 켠다.
- **도착 판정**: 잰 이동이 예상과 `ARRIVE_PX`(60px) 또는 12% 안이면 도착, 더 짧으면 지도 끝(벽)에 막힌 것.
- **벽**: 지도 끝 너머로 끌면 지도가 따라갔다가 되튕긴다. 앱이 찍는 순간(놓고 약 0.5초)에는 무른 벽 쪽 지도가 아직 돌아오는 중일 수 있어서, 튕김 확인(`ReboundWindow`)이 화면 두 장을 끈 축으로 밀어 보며 돌아오는 속도를 잰다. 되튕김을 잡으면 반대로 끌어 세우고(`ReverseRebound`) 그 자리를 '벽 기억'에 적는다.
- **추정(guessed) 표시**: 위치를 확실히 못 잰 끌기 뒤의 사진에 붙는다. 붙이기가 그 사진의 끈 위치를 덜 믿는다. 한 번 켜지면 기준 사진으로 진짜 자리를 찾을 때까지(`TryRecover`) 유지되고, 결과가 '부분 완료(partial)'가 된다(5장).
- **화면 요소**: 붙박이 UI는 사진들 사이에서 같은 자리·같은 모양인 곳을 배워(`GridParts.LearnStaticUi`) 매칭과 결과에서 뺀다. 공지 패널 자리는 고정 금지 구역(`FIXED_UI`)으로 결과에서만 뺀다.
- **마우스 잠금**(`MouseGuard`): 저수준 마우스 훅(WH_MOUSE_LL). 사용자가 직접 넣는 움직임·휠·버튼은 막고, 앱이 넣는 입력('주입됨' 표시가 있음)은 통과시킨다. 클릭 = 멈춤, `Esc`·멈추기 키 = 멈춤(`KeyLatch`). 움직이거나 휠을 굴리면 원신 위 띠로 멈추는 법을 알린다(6초에 한 번까지). 끝·멈춤·오류 모두 마우스를 돌려준다.
- **입력 직전 확인**: 입력 하나마다 원신 창이 맨 앞인지, 창 위치·크기·프로세스가 그대로인지 본다. 원신이 앞에서 벗어나면 앱이 누른 버튼만 놓고, 원신이 5초 안정되게 돌아올 때까지(최대 120초) 기다린다.
- **키 설정**: 시작·멈추기 키는 `작업/설정.json`의 `keys`(윈도우 가상 키 번호와 이름). `Esc`와 마우스 버튼은 고를 수 없다.
- **알림 띠**(`Band`): 시작 예고 3초, 시작 못 함(시작 키를 다시 누를 때까지), 다 찍음 4초, 멈춤 6초, 마우스 잠김 안내 4초. 클릭·포커스를 안 가져가고 화면 캡처에서 빠지는 창이다(그래도 찍는 동안에는 숨긴다).
- **화면 크기**: 칸 크기·지도 영역·화면 요소 자리는 화면 비율로 계산하고, 픽셀로 정한 판정 기준은 화면 너비에 비례하게 바꾼다(`CaptureConsts.ApplyScreenScale`, 1920이면 0.75배).

### 4-3. 붙이기(`GridStitch`·`EngineStitch`)

자동 캡처 사진(모든 사진에 끈 위치 기록 `capture_grid.json`이 있음)은 격자 붙이기, 직접 넣은 사진은 엔진 붙이기를 쓴다.

**격자 붙이기**(`GridStitch`):
- 각 사진의 특징점을 뽑고, 끈 위치가 가까운 이웃·찍은 순서 이웃 쌍을 비교한다.
- 쌍을 받는 기준: 맞는 점 `TRUST_STRONG`(150) 이상이거나, 끈 위치 기록과 `PRIOR_TOL`(80px) 안. 전체 위치를 최소제곱으로 푼 뒤 `FIT_TOL`(30px) 넘게 어긋나는 연결은 뺀다.
- 화면 테두리의 붙박이 점(같은 자리·같은 모양)은 매칭 전에 뺀다. 안 그러면 움직인 두 화면이 '안 움직임(0,0)'으로 맞았다고 나온다.
- 매칭으로 큰 묶음에 안 이어진 묶음은 끈 위치(1표)·약한 매칭(0.5표)·촘촘 맞추기(1표) 다수결로 놓는다. 추정 표시 사진의 끈 위치는 0.25표.
- 한도: 비교 쌍 수, 비교 시간(900초), 결과 넓이. 위치가 끈 위치보다 2배 넘게 퍼지면 합성하지 않는다.
- 화면에 더해진 빛 빼기: 게임 지도 화면은 가장자리에 푸른 빛이 얇게 더해져 있어서, 이음매를 찾기 전에 화면 자리별 '더 밝은 양'을 그 판의 사진끼리 견줘 재서 뺀다(사진 12장 미만이거나 못 재면 안 뺀다).
- 이음매: 겹친 사진을 평균 내지 않는다(해안선이 사진마다 움직여 흐려짐). GraphCut(COST_COLOR, 1/4 크기)으로 두 사진이 가장 비슷한 곳에 이음매를 낸다.
- 플레이어 방향 화살표는 결과에서 빼고 다른 사진으로 채운다. 어느 사진으로도 못 덮는 곳은 그대로 둔다.
- 자리를 검증 못 한 사진 묶음은 결과에 안 넣고 `미확인_사진/`에 둔다.
- 실시간 붙이기: 쌍마다 `[live] A B 받아들임 dx dy` 줄을 찍고, 앱이 첫 사진부터 이어 붙인 자리를 화면에 보낸다.

**엔진 붙이기**(`EngineStitch`, 직접 넣은 사진): 파일 이름 순서로 가까운 쌍부터(1칸 차, 2칸 차 …) 맞춰 보고, 최소 3칸 차까지 본 뒤 전체가 이어지면 멈춘다. 점수 큰 쌍부터 최대 신장 나무로 자리를 정하고, 가운데가 센 가중 평균으로 합친다. 화면 아래 가운데 버튼 자리와 게임 UI 자리는 뺀다.

### 4-4. 다듬기(`EdgeTrimmer`)

경계선(청록·회색) 바깥을 자르고 바깥 얼룩을 지운다(0.5배로 계산). 다듬은 뒤 지도 점이 0.5% 넘게 같이 잘리면 경고한다(정상 0.1% 안팎). 마지막에 고른 다듬기 설정을 기억해 다음 자동 다듬기에 쓴다.

## 5. 확인된 사실과 알려진 한계

### C# 판에서 확인한 것(2026-11-15, 개발 PC)

- **실제 원신 두 판**(끝까지 축소, 앱 안 찍기 → 자동 붙이기·다듬기까지): 기본 지도 300초·118장·끌기 176번, 이벤트 그림체 지도 371초·159장·끌기 220번. 둘 다 완료, 추정 0장, 모든 사진이 붙음. 끌기 보정 g는 1.0152·1.2407로 같은 지도의 파이썬 판(1.0141~1.0151·1.2385~1.2434)과 0.003 안. 앱이 믿은 사진 자리와 합친 자리의 차이는 최대 29.6·28.9px. 다 찍은 뒤 앱 창이 앞으로 왔다. 이벤트 그림체 지도는 파이썬 판(419~441초)보다 약 1분 빨랐다. 아래 '실측' 절의 나머지 값은 같은 방식의 파이썬 판으로 잰 것이다.
- 파이썬 판과 같은 입력에 같은 결과가 나오는지 견줬다: 찍기 시뮬레이터 27장면 중 25장면은 끌기 하나하나의 판단·자리와 찍은 사진 이름·자리까지 같았다. 나머지 2장면은 파이썬 판이 계산 잡음(float32 FFT)으로 엉뚱한 이동 봉우리를 고른 곳에서 갈렸고, 그 계산만 더 정밀하게(float64) 바꾼 파이썬과는 C#이 완전히 같았다. 실제 사진 작업을 붙이고 다듬은 결과(사진 자리·목록·그림), 직접 넣은 사진 붙이기, 앱 화면이 쓰는 `/api` 응답도 파이썬 판과 견줬다.
- 시험 창에서 잰 것: 끌기 구간 시간이 파이썬 판과 ±10ms 안, 8ms 걸음이 평균 8.3ms. 화면 찍기는 그린 무늬와 화소가 같았고 한 장 약 12ms(파이썬 판 약 89ms). 알림 띠는 화면 찍기에 안 들어갔다. 마우스 잠금: 잠긴 동안 손으로 움직여도 커서가 0px 움직였고 안내 띠가 떴으며, 클릭·`Esc`로 바로 멈추고 풀렸다.
- 붙이기는 같은 110장 작업에서 C# 약 155초·파이썬 약 205초, 다듬기 약 13초·20초였다.

### 실측으로 확인한 것(파이썬 판, 개발 PC: 2560×1440, 한국어 클라이언트)

- 끌기 모형(4-2)은 무작위 사전 예측 오차 0.94% 안.
- 벽마다 되튕김이 다르다. 단단한 벽은 0.25초쯤에 돌아오고, 무른 벽(예: 이나즈마 동·남)은 시간 상수 약 1.1~1.8초로 천천히 돌아오며 벽 너머로 85~95% 따라간다.
- 해안선 바깥 청록 띠는 프레임마다 깜빡이고, 별빛 배경은 지도와 따로 흐른다. 그래서 해안선만 보이는 화면에서는 '멈췄나' 판정이 비교 간격 0.3초 이하면 늘 되고, 1.2초 이상이면 안 된다.
- 전체 화면과 창 모드 모두 찍힌다.
- 이벤트 그림체 지도는 화면 아래쪽 가장자리에 붙은 빛 효과가 위로 흐른다(0.15초에 약 2.7px). 그래서 멈춤 판정은 화면 가장자리 띠(위 20%·아래 30%·좌우 8%, `SETTLE_CENTER`)를 빼고 가운데 점만 쓴다. 이 폭은 이 그림체·2560×1440에서 잰 값이다.
- 한 판(실제 4판, 끝까지 축소): 기본 지도 약 4.5분(110~111장, 추정 0장, 완료), 이벤트 그림체 지도 약 7~7.5분(155~160장). 앱이 믿은 사진 자리와 합친 자리의 차이는 최대 21~50px.

### 알려진 한계

1. **마우스를 4.5~7.5분 잡는다**(파이썬 판 실측). 앱 안내 문구는 넉넉히 '6~8분'이다.
2. **추정 표시가 켜지면 근처에 기준 사진이 있을 때만 풀린다.** 추정 중에는 '예상과 맞음' 끌기 뒤에도, 1.3칸 안에 추정 아닌 사진이 있으면 가까운 2장과 맞춰 진짜 자리를 찾는다(`TryRecover`, 한 번 1초·판당 15초). 기준 사진이 먼 구간이 길면 그동안은 안 풀린다. 추정 사진이 1장이라도 남으면 결과는 '부분 완료'로 나온다.
3. **지도 바깥(별만 보이는 곳)에서는 시작하지 못한다.** 다시 기다리며 알려 주지만, 앱이 스스로 땅을 찾아가지는 않는다.
4. **실측은 2560×1440 한 대에서만 했다.** 1080p·다른 화면 비율에서 실제로 찍어 보지는 않았다. 1080p는 사진 한 장의 픽셀이 적어서 결과 그림이 그만큼 작고 덜 선명하다.
5. **한국어 클라이언트만** 시험했다(패널 글자 길이·위치가 다를 수 있음).
6. 넓은 민무늬 바다·별빛 구간에서는 위치를 못 재는 끌기가 생기고, 붙이기도 끈 위치에 기대어 놓는다. 빠른 확인 점수 문턱 때문에 맞게 간 끌기가 '모름'이 되어 추정이 켜진 일이 실제로 한 번 있었다(결과 그림은 정상).
7. 끈 축 밀어 보기는 한쪽 그림의 무늬가 거의 없는 겹침(빈 하늘·바다)에서 점수가 계산 잡음에 흔들릴 수 있다. 파이썬 판은 이 잡음 때문에 점수가 1을 넘는(원래 불가능한) 봉우리를 받아들인 적이 있고(시뮬레이터, 던져진 끌기), C# 판은 계산이 더 정밀해 그런 봉우리가 거의 안 생긴다. 그래서 그런 화면에서는 두 판이 다른 길로 갈 수 있다. 점수 > 1을 버리는 규칙은 아직 넣지 않았다.
8. Windows 전용, 관리자 권한이 필요하다.
9. **이벤트 지도나 지도 확장 업데이트와는 호환되지 않을 수 있다.** 지도 그림체·바다와 배경 색·경계선 모양·화면 요소(패널·버튼 자리)가 바뀌면, 지도 점 판정·벽 판정·화면 요소 빼기·가장자리 다듬기 기준이 안 맞을 수 있다. 지도 화면 배치가 바뀌면 고정값(`CONTENT_BOX`·`FIXED_UI`·`PARK_AT`)을 다시 맞춰야 할 수 있다.
10. 가장자리 다듬기는 지도 바깥(별빛 공간)에서부터 '바깥'을 칠해 들어오는 방식이라, 청록 경계선이 끊긴 곳이 있으면 그 틈으로 안까지 잘려 나갈 수 있다. 밝은 땅은 벽으로 더해 못 넘게 했지만 어두운 바다는 막지 못한다. 지도가 0.5% 넘게 잘리면 경고한다. 잘린 곳은 「합친 그대로」 지도에는 남아 있다.
11. **끝까지 축소한 화면만 지원한다.** 확대한 채로 찍으면 한 칸이 지도에서 차지하는 넓이가 작아져 사진 수 한도(기본 300장, 「설정」의 최대 사진 수)에 걸려 다 못 찍고, 한 화면에 땅이 적어 넓은 바다에서 자리를 잃는다. 앱은 준비 화면에서 경고만 하고, 확대 정도를 스스로 알아채지는 않는다(끝까지 축소해도 기본 지도 g≈1.01·이벤트 그림체 g≈1.24로 지도마다 달라 g로 가리기 어렵다).
12. 직접 넣은 사진 붙이기는 사진들이 같은 크기여야 한다. 파일 이름 순서가 찍은 순서와 크게 다르면 더 먼 쌍까지 비교하느라 오래 걸린다. 다른 사진과 겹치는 곳이 없는 사진이 있으면 합치지 못하고 어느 사진이 안 이어졌는지 알려 준다.
13. **임무 추적을 켠 채 찍으면 노란 추적 표시가 결과에 남을 수 있다.** 추적 목표가 화면 밖에 있으면 원신은 노란 마름모와 방향 화살표를 화면 가장자리에 붙여 보여 준다. 이 표시는 끄는 방향에 따라 가장자리를 타고 자리를 옮기므로 '안 움직이는 화면 요소' 빼기(`LearnStaticUi`)에 걸리지 않는다. 겹친 곳에서 어느 사진을 쓸지는 이음매(`SeamMasks`, 그래프컷)가 색 차이만 보고 정하기 때문에, 표시가 든 사진이 뽑히면 그대로 남는다(2026-11-16 C# 판 실제 판에서 1곳). 추적 목표가 화면 안에 있을 때의 표시는 지도 위 진짜 자리라 남는 게 맞다. 앱은 준비 화면에서 끄라고 안내만 한다. 고친다면 플레이어 화살표처럼(`PointerMask`) 가장자리의 노란 표시를 찾아 그 사진에서 '쓰지 말 곳'으로 빼면 된다.

### 게임 없이 고치고 확인하기

- 붙이기·다듬기는 명령으로 따로 돌릴 수 있다. 앱이 자식 프로세스로 쓰는 것과 같은 명령이다. `GenshinMap.exe`는 관리자 권한을 요구하므로, 관리자 아닌 창에서는 개발용 콘솔(`src/Cli`, 관리자 아님)을 쓴다.
  ```
  dotnet run --project src/Cli -c Release -- stitch <input 폴더> <capture_grid.json> -o 결과.png --exclude 1024,1310,1536,1440
  dotnet run --project src/Cli -c Release -- trim 결과.png -o 다듬음.png --target-line cyan --margin 70 --process-scale 0.5 --close 35 --wall-thickness 7 --upscale-smooth 7 --mask-smooth 9 --final-close 5 --crop --debug debug_trim
  dotnet run --project src/Cli -c Release -- engine <사진 폴더> -o 결과.png --devignette 0.38 --pair-search progressive --min-gap-before-stop 3
  ```
  `--exclude`의 네 값은 2560×1440 기준 화면 아래 가운데 버튼 자리다(앱은 사진 크기의 40~60%·91~100%로 계산한다, `Job.ExcludeArgs`). 같은 입력이면 같은 위치가 나와야 한다(`grid_stitch_log.json`의 `positions` 비교).
- 찍기 루프(`FastCapture`)는 화면·시계·보고를 인터페이스(`IScreen`·`IClock`·`IReporter`)로만 받는다. 실제 판은 `GenshinScreen`·`PreciseClock`을 꽂는다. 큰 지도 그림 한 장으로 게임 화면을 흉내 내는 시험용 화면을 직접 만들어 꽂으면 마우스 없이 찍기를 돌릴 수 있다(개발할 때 쓴 흉내 화면·시험 도구는 이 저장소에 넣지 않았다).
- 같은 입력이면 늘 같은 답이 나오게 하려면 흉내 화면 쪽에서 시계를 가짜로(잠자기 = 시계만 앞으로) 두면 된다. 실제 판에서만 사진 저장이 따로 도는 일꾼으로 가고, 흉내 화면(`IsReal = false`)에서는 그 자리에서 저장한다.

### 고칠 때 지키면 좋은 것

- 고치기 전 파일을 따로 복사해 둔다(또는 git으로).
- **진짜 마우스를 쓰는 시험(실제 원신)은 그 PC 사용자에게 먼저 알리고 허락을 받는다.** 가능하면 흉내 화면이나 시험 창으로 먼저 시험한다.
- 판단 규칙을 바꾸면 같은 사진들로 다시 붙여서 결과 그림을 지난 성공 판과 눈으로도 비교한다. 숫자 검증이 좋아도 땅 없는 바다 사진은 못 잴 수 있다.
- 시간을 재서 판단하는 곳(끌기 걸음 8ms, 놓기 전 0.4초, 멈춤 기다림 0.15초 간격 등)은 실측에 맞춘 값이다. `Thread.Sleep`으로 바꾸지 말고 `IClock.Sleep`(실제 판 `PreciseClock`)을 쓴다.
- 화면(`web/`)은 앱이 주는 `/api` JSON 모양에 기대어 그린다. `Api`·`Job.State()`의 열쇠 이름을 바꾸면 `web/app.js`도 같이 고친다.
- 숫자를 글자로 바꿀 때는 문화권 무관(`InvariantCulture`)으로 쓴다(자식 프로세스 출력 줄을 앱이 다시 읽는다).
- 화면 문구는 존댓말, 개발용 수치는 기록 파일에만.
